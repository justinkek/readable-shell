# Updating readable-shell

Running this skill is the go-ahead. Update, then say which version was
installed and which one is now.

The commands are below.

Stop and ask before anything they do not carry, and before a command that
removes an install rather than moving it forward.

## Afterwards

A session already running holds the old copy. The steps below say how to load
the new one, and what a hook prints comes from the copy that is loaded, so run
the reload skill after that and not before.

If it was already the latest, say so and change nothing.

## The steps for this install

Installed by the Cloud Session Install Script from
🔗 [the install instructions](https://github.com/justinkek/readable-shell/blob/main/INSTALL.md), where the checkout lives at
`/opt/readable-shell` inside the container.

For every session, edit anything in the Setup script field of your cloud
environment. The edit rebuilds the environment, which runs the script again and
pulls the latest release. An untouched environment rebuilds about weekly on its
own, so it follows releases either way.

For the current session, run `/readable-shell-update`, or ask the agent to
update readable-shell.

(audience: agents) Run the refresh script. Pulling the checkout on its own is not an update.

    printf '{}' | /opt/readable-shell/distributions/claude-code-cloud/refresh.sh

(audience: agents) Then run the session start hook again, since the copy in the
menu is the one loaded before the update:

    printf '{}' | /opt/readable-shell/distributions/claude-code-cloud/hooks/load-rules.sh

Run `/reload-skills` when you want the menu to list the new copy. The skills on
disk are already the new ones, and an agent reads them there.
