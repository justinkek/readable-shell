# readable-shell for Claude

(audience: humans)

## What works

### Claude Code, on your machine

Every hook runs: the rules are printed when a session starts, and a command or
an edit to a shell file that breaks them is refused before it runs. Settings are
kept in `~/.readable-shell`, or in a project's own `.readable-shell/settings`.

Not yet verified on a real session.

### Claude Chat

No hook runs, so nothing is refused. The rules arrive only when the reload skill
prints them, and a session is asked to follow them rather than held to them.

Not yet verified on a real session.

## Installing

### Claude Code, on your machine

    claude plugin marketplace add justinkek/readable-shell
    claude plugin install readable-shell@readable-shell

(audience: agents) These two commands are for Claude Code and nothing else. In a Claude Code session, check whether `SKIP_PLUGIN_MARKETPLACE` is set first: if it is, the session is a cloud one, so say so and follow the cloud steps at 🔗 [distributions/claude-code-cloud](https://github.com/justinkek/readable-shell/tree/main/distributions/claude-code-cloud) instead.

### ZCode

Open Settings, then Plugin Management, then Discover, and add
`justinkek/readable-shell` with the `+` button. It installs the same plugin
as Claude Code does.

The hooks load when a session starts, so the session you installed from does
not have them: open a new one, or reload the plugins in this one.

The bundled command line cannot install a plugin, but it does say what is
installed:

    node /Applications/ZCode.app/Contents/Resources/glm/zcode.cjs plugins list

(audience: agents) You cannot do this part: the window is the person's to
click. Print these steps for them and stop.

### Claude Chat

Open the plus menu beside the message box, then Plugins, then Browse plugins,
and install readable-shell. Its skills appear under the plugin's own entry
in that menu.

No hook runs in Chat, so nothing the plugin would print at session start
reaches a conversation on its own. Ask for the reload skill in your first
message and it prints it; a preference or a custom style holding the same text
does it without asking.

Nothing reads a settings file either, so a setting you ask for lasts as long as
that conversation does.

(audience: agents) You cannot do this part: the window is the person's to
click. Print these steps for them and stop.

### Claude Cowork

Open the plus menu beside the message box, then Plugins, then Browse plugins,
and install readable-shell. Its skills appear under the plugin's own entry
in that menu.

The hooks run here, so a conversation started after the install gets what the
session start hook prints. One started before it gets nothing until you ask for
the reload skill.

Settings are written inside the session's container, which is discarded when the
session ends.

click. Print these steps for them and stop.

## Updating

### Claude Code, on your machine

    claude plugin marketplace update readable-shell
    claude plugin update readable-shell@readable-shell

Load the new copy into a session already running by restarting it or running
`/reload-plugins`.

If the version does not move, the marketplace snapshot is stale: the first of
the two commands failed or was skipped.

Your settings are in `~/.readable-shell` and no install touches them.

### ZCode

Update it under Settings, Plugin Management, where it was added. The bundled
command line cannot install or update a plugin, so the only way in is the
window.

Your settings are in `~/.readable-shell` and no update touches them.

### Claude Chat

Open the plus menu, then Plugins, then Manage plugins, and update it there.

### Claude Cowork

Open the plus menu, then Plugins, then Manage plugins, and update it there.

## Uninstalling

### Claude Code, on your machine

    claude plugin uninstall readable-shell@readable-shell
    claude plugin marketplace remove readable-shell
    rm -rf ~/.readable-shell

The last of the three takes the settings and the state with it, so nothing is
left.

### ZCode

Remove it under Settings, Plugin Management, where it was added.

    rm -rf ~/.readable-shell

That takes the settings and the state with it, so nothing is left.

### Claude Chat

Open the plus menu, then Plugins, then Manage plugins, and remove it there.

Nothing here writes `~/.readable-shell`, so the removal leaves nothing behind.

### Claude Cowork

Open the plus menu, then Plugins, then Manage plugins, and remove it there.

`~/.readable-shell` is inside the session's container, which is discarded when
the session ends, so nothing is left after that.
